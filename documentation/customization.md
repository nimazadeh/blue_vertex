# راهنمای سفارشی‌سازی Blue Vertex

> نسخهٔ ۲٫۴٫۱ — این راهنما دو مسیر دارد: **الف)** برای همه (ویرایش خروجی، بدون هیچ ابزاری) و **ب)** برای کسانی که به سورس پروژه دسترسی دارند (ویرایش مولدها — در بسته‌های بازار موجود نیست).

---

## الف) سفارشی‌سازی مستقیم (برای همه — بستهٔ بازار و سورس پروژه)

اگر بسته Preview دارید یا فقط ظاهر/متن‌ها را عوض می‌کنید، با فایل‌های خروجی کار می‌کنید. هیچ ابزاری لازم نیست.

### ۱. رنگ‌ها و توکن‌های طراحی

همهٔ رنگ‌ها، فاصله‌ها و سایه‌ها به‌صورت متغیرهای CSS در ابتدای `assets/css/base.css` تعریف شده‌اند:

| چیزی که می‌خواهید عوض کنید | کجا |
|---|---|
| رنگ برند آبی | `--blue-600` (پیش‌فرض `#2563EB`) و خانواده‌ی `--blue-*` در `:root` |
| آبی الکتریکی (اکسنت) | `--blue-400` / `--sky-*` در `:root` |
| پس‌زمینه و سطوح تیره | `--bg`, `--surface-1/2/3`, `--border` در `:root` |
| نسخهٔ روشن از همهٔ همین‌ها | همان متغیرها داخل `:root[data-theme="light"]` |
| فاصله‌ها | `--space-*` / شعاع‌ها `--radius-*` / سایه‌ها `--shadow-*` |

مثال — تغییر رنگ برند به بنفش:

```css
:root {
  --blue-600: #7C3AED;  /* بود پیشین: #2563EB */
}
:root[data-theme="light"] {
  --blue-600: #6D28D9;  /* نسخهٔ روشن تیره‌تر بماند */
}
```

فقط همین — دکمه‌ها، لینک‌ها، نمودارها (با رویداد `bv:theme`) و پنل ادمین همگی از همین توکن می‌خوانند.

### ۲. فونت

فونت فعلی **وزیرمتن** است (مجاز OFL — فایل `assets/fonts/OFL.txt`). برای تعویض:

1. فایل‌های woff2 فونت جدید را در `assets/fonts/` بگذارید و نام/وزن‌ها را در بلوک‌های `@font-face` ابتدای `assets/css/base.css` اصلاح کنید.
2. اگر می‌خواهید حالت دابل‌کلیک (`file://`) هم فونت درست نشان دهد، فایل `assets/css/fonts-embed.css` را دوباره بسازید: همان `@font-face`ها ولی با `src: url(data:font/woff2;base64,....)` به‌جای مسیر woff2. اسکریپت head به‌صورت خودکار آن را فقط در پروتکل `file:` لود می‌کند.

### ۳. متن‌ها

- **بسته Preview:** متن هر صفحه مستقیم در همان فایل HTML است — جستجو و ویرایش.
- **بسته Developer:** متن‌ها در ماژول مولد صفحه (مثلاً عنوان هیرو در `tools/marketing_home.py`) — ویرایش کنید و `python3 tools/build.py` بزنید.

### ۴. داده‌های نمایشی پنل مدیریت

همهٔ داده‌های ادمین (کاربران، سازمان‌ها، فاکتورها، تیکت‌ها، رویدادهای امنیتی و…) در یک فایل است:

```
assets/js/admin-data.js  →  window.ADMIN = { users: [...], orgs: [...], ... }
```

نام، ایمیل، مبلغ، وضعیت و شناسه‌ها را در همین آرایه‌ها عوض کنید؛ هر ۱۳ صفحهٔ ادمین به‌صورت زنده از همین مدل می‌خوانند و هماهنگ به‌روز می‌شوند. قرارداد فیلدها در ابتدای همان فایل به‌صورت کامنت مستند است.

### ۵. تصویر اشتراک‌گذاری و آیکون

| مورد | مسیر |
|---|---|
| تصویر OG/Twitter (1200×630) | `assets/og/og-cover.jpg` |
| فاب‌آیکون | `assets/icons/favicon.svg` |

### ۶. دامنه و canonical

اگر محصول را روی دامنهٔ خود می‌گذارید:

1. در هر فایل HTML، مقدار `href` تگ‌های `<link rel="canonical">` و `<meta property="og:url">` را عوض کنید (جستجوی `bluevertex.ir` در همهٔ فایل‌ها).
2. در `sitemap.xml`، URLها را عوض کنید.
3. در بستهٔ Developer کافی است فقط `SITE` در `tools/build.py` را عوض و بیلد بگیرید — canonical/og:url/سیت‌مپ همه خودکار به‌روز می‌شوند.

## ب) سفارشی‌سازی از طریق مولدها (فقط سورس پروژه — در بسته‌های بازار موجود نیست)

> مولدها (`tools/`) بخشی از سورس پروژه‌اند و **در بسته‌های فروشگاه قرار ندارند**. اگر فقط فایل‌های خرید را دارید، مسیر **الف)** را استفاده کنید.

**قاعدهٔ طلایی (در سورس پروژه):** HTML خروجی مولدهاست؛ مستقیم ویرایشش نکنید.

1. **برند و قاب سراسری** (ناوبری، فوتر، `<head>، پالت فرمان): `tools/chrome.py` — توابع `head()`، `navbar()`، `footer()`، `scripts()`.
2. **دامنه و خروجی‌های SEO:** `SITE` در `tools/build.py`.
3. **محتوای هر صفحه:** ماژول مولد مربوطه — لیست کامل در بخش «معماری مولد» README:
   - خانه: `tools/marketing_home.py`
   - ۷ صفحهٔ بازاریابی: `tools/marketing_pages.py`
   - بلاگ/تماس: `tools/blog_contact.py`
   - احراز: `tools/auth.py`
   - مستندات: `tools/docs_content.py` / `docs_content2.py`
   - داشبورد: `tools/dash.py` / `dash2.py` / `dash3.py`
   - چنج‌لگ/وضعیت: `tools/misc.py`
   - ادمین: `tools/admin.py`
4. **صفحهٔ جدید:** تابع بیلد بسازید (از `chrome.head()`, `chrome.navbar()`, `chrome.footer()`, `chrome.scripts()` استفاده کند) و یک خط `emit('path.html', build_fn(prefix))` به `b()` در `build.py` اضافه کنید. canonical/og:url/سیت‌مپ خودکار درست می‌شوند. برای خروج از ایندکس (مثل ادمین)، مسیر را به لیست `Disallow` در `seo_extras()` اضافه کنید.
5. **داده‌های نمونه:** در ابتدای توابع مولد به‌صورت لیست‌های خوانا (مثلاً مشتریان در `marketing_pages.py`، داده‌های ادمین در `admin-data.js`).

### چرخهٔ توسعه

```bash
python3 tools/build.py    # بازتولید (پایتون ۳٫۸+، بدون وابستگی)
python3 tools/qa.py       # گیت: باید ۰ خطا / ۰ هشدار
# اختیاری: node tools/smoke.js و باطری‌های qa1–4 (راهنما در README)
```

## چه چیزی را نباید تغییر دهید (بدون نیازمندی خاص)

- **`dir="rtl"` و `lang="fa"`** روی `<html>` — حذفشان RTL را می‌شکند.
- **ویژگی‌های منطقی CSS** (`*-inline*`) — اگر `left/right` فیزیکی اضافه می‌کنید، آینه‌شکنی رخ می‌دهد.
- **اسکریپت anti-FOUC** در ابتدای `<head>` — حذفش باعث پرش تم در اولین رندر می‌شود.
- **`data-icon` برای آیکون‌ها** — رندرکنندهٔ Lucide در `main.js` روی همین صفت تکیه دارد.
