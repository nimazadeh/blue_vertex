# بلو ورتکس — Blue Vertex

> قالب HTML استاتیک پلتفرم توسعه‌دهنده، فارسی‌اول و راست‌به‌چپ (RTL)
> محصول بلو استودیو (Blue Studio) — نسخه ۲٫۴٫۰

بلو ورتکس یک قالب استاتیک کامل برای فروش در بازار ایران است: یک پلتفرم توسعه‌دهنده خیالی (با داده‌های نمونه‌ی واقعی) شامل سایت بازاریابی، مستندات زنده، مرجع API، وضعیت سرویس، تغییرات (Changelog)، صفحات احراز هویت و یک داشبورد ۱۱ صفحه‌ای توسعه‌دهنده. همه‌چیز به فارسی، با تاریخ شمسی، اعداد فارسی و فونت وزیرمتن — بدون هیچ وابستگی به CDN و بدون بک‌اند.

## مشخصات کلی

| ویژگی | مقدار |
|---|---|
| زبان محصول | فارسی (تنها زبان رابط کاربری) |
| جهت‌گیری | راست‌به‌چپ پیش‌فرض (`<html lang="fa" dir="rtl">`) با جزیره‌های LTR برای محتوای فنی |

| کتابخانه‌های محلی | Chart.js 4.4.4، Lucide Icons 0.446.0، Prism.js 1.29.0 (۱۳ کامپوننت) — همه به‌صورت فایل محلی |

| قیمت‌گذاری | تومانی و واقعی (مثلاً ۹۹۰٬۰۰۰ تومان در ماه) |

| بدون نیاز به شبکه | کاملاً آفلاین — همه فونت‌ها و اسکریپت‌ها محلی هستند |

## اجرای سریع

قالب به‌صورت فایل استاتیک است و روی هر هاست ساده‌ای اجرا می‌شود:

```bash
# گزینه ۱ — هر سرور استاتیک دلخواه (Nginx، هاست اشتراکی، Netlify و…)
# فقط کافی است پوشه پروژه را آپلود کنید.

# گزینه ۲ — سرور توسعه محلی پایتون
python3 -m http.server 8080
# سپس http://localhost:8080 را باز کنید

# گزینه ۳ — Node.js
npx serve .
```

> نکته: باز کردن مستقیم فایل‌ها با `file://` (دابل‌کلیک روی HTML) هم کار می‌کند — این اسکریپت کوچک در `<head>` وقتی پروتکل `file:` باشد، فونت وزیرمتن را به‌صورت data-URI داخلی (`assets/css/fonts-embed.css`) بارگذاری می‌کند تا خطای CORS فونت رخ ندهد. روی HTTP همچنان فایل‌های woff2 بهینه لود می‌شوند. فقط برای دیدن پیش‌نمایش زنده یا توسعه، سرور ساده پیشنهاد می‌شود (`python3 -m http.server 8801`).

### استقرار (Deploy)

خروجیِ هر بیلد کاملاً استاتیک است و روی هر میزبانی اجرا میشود — هاست اشتراکی ایران، Nginx، Netlify، Vercel یا GitHub Pages:

```bash
# بازتولید کامل خروجی (پس از هر تغییر در tools/)
python3 tools/build.py
```

- `robots.txt`، `sitemap.xml` و `404.html` بهصورت خودکار با هر بیلد ساخته میشوند (صفحات ادمین/داشبورد/ورود از ایندکس خارجاند).
- `sitemap.xml` فقط صفحات عمومی را شامل میشود؛ URL پایه `https://bluevertex.ir/` است — اگر دامنهٔ دیگری دارید، `SITE` را در `tools/build.py` عوض کنید.
- صفحهٔ ۴۰۴ استایلدار است؛ در Netlify/Vercel بهصورت پیشفرض استفاده میشود، در Nginx با `error_page 404 /404.html;` فعال کنید.

## طراحی و هویت بصری

- **زمینه تیرهٔ نرم‌شده (پیش‌فرض):** پس‌زمینه `#0B0D12` (به‌جای مشکی خالص)، سطوح خاکستری-سرمه‌ای `#151922` تا `#232A37`، آبی برند `#2563EB`، آبی الکتریکی `#38BDF8`، حاشیه‌ها `rgba(255,255,255,.09)` — بدون مشکی خالص `#000`.
- **تم روشن کامل:** با نگاشت توکن‌ها؛ زمینه `#F4F6F9`، سطوح سفید `#FFFFFF`، متن `#111827`، حاشیه‌ها `rgba(15,23,42,.11)`، اکسنت‌های متنی تیره‌تر (`#1D4ED8`) برای خوانایی روی سفید. بلوک‌های کد در هر دو تم تیره می‌مانند (`--code-bg`).
- **درخشش محدود:** گلوی استراحت‌شده (glow) و گرید/نویز ظریف؛ هیچ جلوه نئونی گیمینگ‌گونه‌ای وجود ندارد.
- **توکن‌های CSS:** رنگ‌ها، فاصله‌ها، تایپوگرافی، سایه‌ها و انیمیشن‌ها به‌صورت متغیرهای CSS در `base.css` تعریف شده‌اند. تغییر تم در چند ثانیه با تغییر توکن‌ها ممکن است.
- **انتخاب‌گر رنگ (Accent Picker):** در تنظیمات داشبورد، ۴ پالت (آبی، آبی آسمانی، بنفش، سبز) با جابه‌جایی متغیرهای CSS — بدون رفرش صفحه.

### سیستم تم (حالت نمایش تاریک/روشن)

- **مکانیزم:** تم با صفت `data-theme` روی `<html>` انتخاب می‌شود (`data-theme="light"` = روشن؛ نبودِ صفت یا `data-theme="dark"` = تیرهٔ نرم). تمام کامپوننت‌ها فقط از توکن‌ها می‌خوانند، پس کل محصول (مارکتینگ، مستندات، داشبورد، ادمین) یکجا تغییر می‌کند.
- **بدون فلش:** یک اسکریپت کوچک در `<head>` (قبل از CSS) تم را از `?theme=light|dark` یا `localStorage['bv-theme']` می‌خواند و صفت را پیش از اولین رندر می‌نشاند؛ هیچ پرش تیره→روشن وجود ندارد.
- **جای دکمه‌ها:** نوار بالای سایت + منوی موبایل (`data-theme-toggle` با تعویض آیکون خورشید/ماه)، نوار بالای داشبورد و ادمین، و بخش «حالت نمایش» در تنظیمات داشبورد (سگمنت تاریک/روشن با `data-theme-opt`).
- **نمودارها:** `assets/js/charts.js` رنگ‌ها را از توکن‌ها می‌خواند و با رویداد `bv:theme` نمودارها را بدون رفرش دوباره رسم می‌کند.
- **ذخیره:** انتخاب کاربر در `localStorage['bv-theme']` ذخیره و در همهٔ صفحات اعمال می‌شود؛ پارامتر `?theme=` بر localStorage اولویت دارد.

جزئیات کامل (تایپوگرافی، شبکه، حالت‌های کامپوننت، اصول RTL و…) در `documentation/design-system.md` آمده است.

## اصول فنی

1. **فارسی‌اول:** همه متن‌ها، برچسب‌ها، خطاها و نمونه‌ها فارسی هستند؛ هیچ متن انگلیسی موازی/دوزبانه‌ای در UI وجود ندارد.
2. **RTL معماری، نه افزونه:** `dir="rtl"` روی ریشه سند؛ در CSS فقط از ویژگی‌های منطقی (`inset-inline`، `margin-inline`، `padding-inline`) استفاده شده است، بنابراین قالب روی هر زبان دیگری هم به‌درستی آینه می‌شود.
3. **جزیره‌های LTR:** URLها، endpointها، JSON، کدهای JS/Python/PHP/Go، cURL، متدهای HTTP، کلیدهای API، ایمیل، نسخه‌ها و دستورات Git با `direction:ltr; unicode-bidi:isolate` راست‌به‌چپ نمی‌شوند.
4. **سیاست اعداد:** اعداد فارسی برای نمایش UI (۱۲۴٬۵۸۰، ۹۹٫۹۸٪) و ارقام لاتین برای شناسه‌های فنی (HTTP 200، v2.4.1، `POST /v1/users`).
5. **تاریخ شمسی:** الگوریتم جلالی (پورت jalaali-js، مجوز MIT با ذکر منبع در کد) در `main.js` پیاده شده و تاریخ روز در بالای داشبورد و تاریخ‌های نمونه در کل محصول شمسی است.
6. **بدون CDN:** تمام کتابخانه‌ها در `assets/js/vendor/` محلی هستند؛ محصول حتی با قطع کامل اینترنت کار می‌کند.
7. **دسترس‌پذیری:** سلسله‌مراتب h1→h6 بدون پرش، `aria-label` برای دکمه‌های آیکونی، برچسب برای همه ورودی‌ها، `aria-live` برای اعلان‌ها، پشتیبانی کامل کیبورد (بستن با ESC، جستجو با Ctrl+K، پیمایش پالت با ↑↓).

## تعاملات شبیه‌سازی‌شده

همه تعاملات با جاوااسکریپت خالص پیاده شده‌اند و کاملاً قابل استفاده‌اند (دمو — بدون بک‌اند):

- **فرمان سریع (Command Palette):** Ctrl/Cmd+K — جستجوی سریع صفحات با پیمایش کیبورد.
- **جستجوی مستندات:** Ctrl+K یا کادر جستجو — فیلتر بر اساس دسته (راهنما/API/SDK/سوالات)، جستجوی اخیر و نتیجه «پیدا نشد».
- **احراز هویت دمو:** فرم‌های ورود/ثبت‌نام با اعتبارسنجی کامل (ایمیل، موبایل ایران، تکرار رمز) و ریدایرکت به داشبورد.
- **داشبورد:** مودال و دراورها (جزئیات درخواست، ساخت کلید، ارتقای پلن، حذف عضو)، تب‌ها، فیلترهای زنده گزارش درخواست‌ها، صفحه‌بندی، کپی با کلیک (clipboard + fallback)، انتخاب بازه زمانی (۷/۳۰/۹۰ روز) با به‌روزرسانی نمودارها.
- **نمودارها:** Chart.js با برچسب شمسی، اعداد فارسی، تورفتگی و tooltip سفارشی.
- **تنظیمات:** ۹ پنل تنظیمات با deep-link (هش #)، تغییر رنگ سازمانی، وب‌هوک با ارسال نمونه، حذف فضای کاری با تایپ دقیق «حذف ابرینو».
- **وضعیت سرویس و تغییرات:** فیلتر دسته‌بندی، انیمیشن نوارهای آپ‌تایم، باز شدن خودکار آکاردئون‌ها.
- **توست‌ها:** سیستم اعلان لحظه‌ای (`aria-live=polite`) برای موفقیت/خطا/هشدار در سراسر محصول.
- **حرکت‌ها:** reveal با IntersectionObserver، هداایتورهای hover، رعایت `prefers-reduced-motion`.

## ابزارهای ساخت و کنترل کیفیت

```bash
python3 tools/build.py    # بازتولید هر ۴۰ صفحه از مولدها (پایتون ۳٫۸+)
python3 tools/qa.py       # گیت QA: ساختار HTML، لینک‌های محلی، توکن‌های ممنوع، lang/dir، متا
node tools/smoke.js       # تست تعاملات ۴۰ صفحه در jsdom
node tools/audit.js       # ممیزی مرورگر واقعی: خطای کنسول، سرریز، فونت، تصویر
node tools/mobile.js      # سرریز افقی در ۳۹۰px (موبایل)
node tools/a11y.js        # ممیزی دسترس‌پذیری خودکار (alt، برچسب، سلسله‌مراتب)

# باطری کامل QA (پایتون + Playwright) — همه ۵۴ صفحه:
python3 tools/qa1_pages.py        # خطاهای کنسول/شبکه در هر صفحه
python3 tools/qa2_responsive.py   # اسکرول افقی واقعی در ۸ عرض (۳۶۰ تا ۱۶۸۰)
python3 tools/qa3_valid_links.py  # اعتبار HTML + لینک‌ها و لنگرهای داخلی
python3 tools/qa4_interact.py     # جاروی کلیک همه کنترل‌ها و فرم‌ها (خطای JS)
python3 tools/audit_admin.py      # ترازبندی و اندازهٔ آیکون‌ها در ۱۳ صفحهٔ ادمین
python3 tools/deep_audit.py       # ID تکراری، آیکون نامعتبر، دکمهٔ مرده، دسترس‌پذیری ادمین
python3 tools/qa_theme.py         # هر دو تم: بوت‌استرپ، کلیدهای تعویض، ذخیره، نمودار، کنتراست
python3 tools/qa_light_sweep.py   # اسویپ تم روشن: ۵۴ صفحه × ۲ عرض (خطای کنسول + سرریز)
```

ابزارهای node نیازمند `npm install --no-save jsdom playwright` هستند (فقط برای توسعه).
اسکریپت‌های QA پایتون نیازمند `pip install playwright html5lib` هستند؛ سرور را از ریشهٔ پروژه اجرا کنید (`python3 -m http.server 8801`).

## نحوه سفارشی‌سازی

1. **تغییر برند:** نام محصول و توضیحات متا در `tools/chrome.py` (توابع `head`، `navbar`، `footer`) و `tools/build.py` ویرایش می‌شود. سپس `python3 tools/build.py` را اجرا کنید.
2. **تغییر رنگ:** توکن‌های `--blue-*` در بالای `assets/css/base.css` را تغییر دهید.
3. **تغییر داده‌ها:** داده‌های نمونه (مشتریان، مقالات، لاگ‌ها، نقشه‌های ابرینو/داده‌پرداز/هوشیار/فراز) در همان فایل مولد مربوطه به‌صورت لیست‌های خوانا تعریف شده‌اند.
4. **حذف اسکریپت‌های توسعه:** پوشه `tools/`، فایل `package-lock.json` و پوشه `node_modules/` باید از بسته فروش حذف شوند.

## پنل مدیریت (Admin Console)

بلو ورتکس چهار لایه دارد: سایت بازاریابی، مستندات، کنسول توسعه‌دهنده (برای مشتریانی که از API استفاده می‌کنند) و **پنل مدیریت** (لایهٔ ۴) برای مالک، اپراتور و تیم پشتیبانی پلتفرم.

### Admin Console چیست؟

یک کنسول عملیاتی سازمانی برای **کنترل‌کنندگان پلتفرم**: «من این پلتفرم را کنترل می‌کنم» — نه «من از این API استفاده می‌کنم». در `admin/` با ۱۳ صفحه ساخته شده است و نگهداری کاربران، سازمان‌ها، اشتراک‌ها، درآمد، مصرف API، فعالیت سیستم، پشتیبانی، محتوا، Feature Flags، امنیت، Audit Logs و تنظیمات سیستم را پوشش می‌دهد.

### تفاوت Developer Console با Admin Console

| | کنسول توسعه‌دهنده (`dashboard/`) | پنل مدیریت (`admin/`) |
|---|---|---|
| کاربر | مشتری/توسعه‌دهنده | مالک، اپراتور، تیم پشتیبانی |
| تمرکز | کلیدها، مصرف، تومانِ خودش | سلامت پلتفرم، مشتریان، درآمد کل |
| حالت ذهنی | «از API استفاده می‌کنم» | «پلتفرم را کنترل می‌کنم» |
| نشانهٔ بصری | برند DEVELOPER CONSOLE | برند ADMIN CONSOLE + نوار شلیم بالایی + نشانگر محیط |
| آدرس | `dashboard/*.html` | `admin/*.html` |

### ساختار صفحات

- **نمای کلی** — ۸ KPI، نمودار MRR و رشد کاربر، سلامت ۸ سرویس، هشدارهای اولویت‌دار، تایم‌لاین
- **کاربران / سازمان‌ها / اشتراک‌ها** — جدول‌های سازمانی با جستجو، فیلتر، مرتب‌سازی، صفحه‌بندی، انتخاب گروهی (bulk) و کشوی جزئیات
- **درآمد** — MRR/ARR/LTV/ARPU/چرخش، فاکتورها، پرداخت‌ها (با دلیل شکست) و بازهٔ ماهانه/هفتگی/روزانه
- **مصرف API** — ترافیک، رتبه‌بندی سازمان‌ها، مرکز خطاها، عملکرد Endpoint (P50/P95/P99)
- **فعالیت سیستم** — تایم‌لاین استقرار/پیکربندی/امنیت + Incidentها با شدت و تیم مسئول
- **پشتیبانی** — تیکت‌ها با اولویت (آیکون + برچسب + رنگ)، گفتگو، یادداشت داخلی، حل تیکت
- **اعلان‌ها / محتوا / Feature Flags** — مرکز اعلان با فیلتر نوع؛ بلاگ/مستندات/Changelog/اعلان؛ توزیع تدریجی با تأیید
- **امنیت** — رویدادهای امنیتی + Audit Logs با نمای قبل/بعد
- **تنظیمات سیستم** — پیکربندی، ماتریس مجوز نقش‌ها، پروفایل و نشست‌ها، **منطقهٔ خطر با تأیید تایپی**

### تعاملات کلیدی

`Ctrl+K` پالت فرمان · `Ctrl+/` جستجوی سراسری · Esc برای بستن هر لایه · تغییر محیط از تاپ‌بار (نشانگر رنگ‌دار) · هر اقدام حساس: مودال تأیید (با تایپ کلمه در منطقهٔ خطر) + ثبت خودکار در Audit Logs · خروجی CSV/JSON شبیه‌سازی با لودینگ و توست.

### نحوهٔ شخصی‌سازی

- **دادهٔ نمایشی:** `assets/js/admin-data.js` — منبع واحد همهٔ موجودیت‌ها (`window.ADMIN`). نام‌ها، ایمیل‌ها، مبالغ و شناسه‌ها را همین‌جا عوض کنید؛ همهٔ صفحه‌ها هماهنگ به‌روز می‌شوند.
- **استایل:** `assets/css/admin.css` (لایهٔ ادمین روی توکن‌های مشترک).
- **منطق تعامل:** `assets/js/admin.js` (جدول‌ها، کشوها، مودال‌ها، پالت، جستجو).
- **تولید صفحه جدید:** یک تابع در `tools/admin.py` بسازید و در `build_all()` ثبت کنید؛ سپس `python3 tools/build.py`.

### نحوهٔ اتصال Backend

این قالب استاتیک است و بک‌اند ندارد؛ برای اتصال واقعی، کافی است داده‌های `admin-data.js` با فراخوانی REST/GraphQL جایگزین شوند (قرارداد فیلدها در همان فایل مستند است). UI هیچ وابستگی به منبع داده ندارد و منطق تعاملات (قبل از هر API) در `admin.js` جداگانه است: ۱) بارگذاری داده → ۲) گرفتن مدل → ۳) `renderTable(entity)` برای رندر مجدد.

### وضعیت کیفیت

- `ADMIN_QA_REPORT.md` — گزارش کنترل کیفیت (مشکلات، ریشه، رفع، تأیید)
- `ADMIN_TRACEABILITY.md` — ماتریس ردیابی نیازمندی‌ها → صفحات → پیاده‌سازی → تست
- ۹۳ تست خودکار DOM پاس (`verify_admin.py` → ALL PASS)؛ صفر خطای کنسول در ۱۳ صفحه؛ ترازبندی آیکون‌ها و چیدمان موبایل (۳۹۰–۱۴۴۰) ممیزی‌شده؛ نمودارهای توزیع با همان کامپوننت داشبورد؛ لایه‌های ۱–۳ بدون تغییر و سالم.
- **QA نهایی محصول (همه ۵۴ صفحه):** صفر خطای کنسول/شبکه (qa1)؛ صفر اسکرول افقی در ۳۶۰/۳۹۰/۴۱۴/۷۶۸/۱۰۲۴/۱۲۸۰/۱۴۴۰/۱۶۸۰ (qa2)؛ HTML معتبر و صفر لینک/لنگر مرده (qa3)؛ صفر خطای JS پس از کلیک روی همهٔ کنترل‌ها و ارسال فرم‌ها (qa4)؛ همهٔ دیپ‌لینک‌ها (`#audit`، `#settings-profile`، `#panel-*`، `#install`) در مرورگر فعال‌اند؛ `robots.txt`/`sitemap.xml`/`404.html` و canonical مطلق و og:image خودکار تولید می‌شوند.

## ایجاد نسخه نهایی

1. `python3 tools/build.py` — اطمینان از تازه بودن صفحات.
2. `python3 tools/qa.py` — گیت QA (باید ۰ خطا و ۰ هشدار باشد).
3. `node tools/audit.js && node tools/mobile.js && node tools/a11y.js && node tools/smoke.js`
4. پوشه‌های `tools/`، `node_modules/` را حذف کنید؛ کل پروژه (بدون آن‌ها) ~۲٫۲ مگابایت است.
5. فایل‌های `documentation/` (مستندات طراحی، گزارش‌های QA/دسترس‌پذیری/ریسپانسیو/RTL و ماتریس ردیابی) را در بسته نگه دارید — اعتماد خریدار را بالا می‌برد.
