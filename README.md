# بلو ورتکس — Blue Vertex

> قالب HTML استاتیک پلتفرم توسعه‌دهنده، فارسی‌اول و راست‌به‌چپ (RTL)
> محصول بلو استودیو (Blue Studio) — نسخه **۲٫۴٫۱**

**English summary:** Blue Vertex is a complete, fully-offline, Persian-first RTL HTML template for a fictional developer platform — marketing site, live documentation with API reference, an 11-page developer console, a 13-page operations admin console, auth, changelog, status and blog. 54 static pages, zero CDN dependencies, local Vazirmatn font, dark/light themes, Persian calendar and digits. Works by double-clicking `index.html` — no server, no Python, no npm needed for preview.

بلو ورتکس یک قالب استاتیک کامل است: یک پلتفرم توسعه‌دهنده خیالی (با داده‌های نمونه‌ی واقعی و هماهنگ) شامل سایت بازاریابی، مستندات زنده، مرجع API، وضعیت سرویس، تغییرات (Changelog)، صفحات احراز هویت، داشبورد ۱۱ صفحه‌ای توسعه‌دهنده و **پنل مدیریت ۱۳ صفحه‌ای**. همه‌چیز به فارسی، با تاریخ شمسی، اعداد فارسی و فونت وزیرمتن — بدون هیچ وابستگی به CDN و بدون بک‌اند.

## اجرای سریع — پیش‌نمایش بدون هیچ وابستگی

**هیچ چیزی نصب نمی‌کنید.** نه پایتون، نه npm، نه سرور:

1. آرشیو را باز کنید (unzip).
2. روی `index.html` **دابل‌کلیک** کنید — تمام.

وقتی فایل با پروتکل `file://` باز شود، یک اسکریپت کوچک در `<head>` فونت وزیرمتن را به‌صورت data-URI داخلی (`assets/css/fonts-embed.css`) بارگذاری می‌کند تا خطای CORS فونت رخ ندهد. روی HTTP فایل‌های woff2 بهینه لود می‌شوند. CSS و تمام تعاملات (تم، پالت فرمان، تب‌ها، مودال‌ها، نمودارها) در هر دو حالت کار می‌کنند.

اگر بخواهید روی مرورگر با آدرس `http://localhost` کار کنید (اختیاری، فقط برای توسعه):

```bash
python3 -m http.server 8080     # یا npx serve .
# سپس http://localhost:8080 را باز کنید
```

### استقرار (Deploy)

خروجی کاملاً استاتیک است و روی هر میزبانی اجرا می‌شود — هاست اشتراکی ایران، Nginx، Netlify، Vercel یا GitHub Pages:

- کل فایل‌ها (HTML + `assets/`) را آپلود کنید. تمام.
- `robots.txt` و `sitemap.xml` همراه محصولند؛ اگر دامنه‌ی دیگری دارید، `SITE` در آن‌ها (و برای بازتولید، در `tools/build.py` سورس ریپازیتوری) را عوض کنید.
- صفحه‌ی `404.html` استایلدار است؛ در Netlify/Vercel به‌صورت پیش‌فرض استفاده می‌شود، در Nginx با `error_page 404 /404.html;` فعال کنید.

## کار با مولدها (سورس ریپازیتوری)

> این بخش مربوط به **سورس ریپازیتوری** (که `tools/` را دارد) است. بسته‌های بازار **هیچ مولد، اسکریپت QA یا ابزار بیلدی ندارند** — برای دیدن و سفارشی‌سازی محصول به هیچ‌کدام از این‌ها نیاز ندارید.

سورس پروژه شامل مولدهای پایتون (`tools/`) است که هر ۵۴ صفحه را تولید می‌کنند. تنها وابستگی: **پایتون ۳٫۸ به بالا** (فقط کتابخانه‌ی استاندارد — هیچ `pip install` برای ساخت لازم نیست).

```bash
python3 tools/build.py    # بازتولید هر ۵۴ صفحه + robots/sitemap/404
python3 tools/qa.py       # گیت QA: DOCTYPE، canonical، ساختار، لینک‌ها، سیت‌مپ (باید ۰ خطا باشد)
```

تست‌های تعاملی (اختیاری، برای توسعه):

```bash
npm install --no-save jsdom playwright    # فقط برای این تست‌ها
node tools/smoke.js                       # تست تعاملات ۴۰ صفحه در jsdom
node tools/audit.js                       # ممیزی مرورگر واقعی (Playwright)
node tools/mobile.js                      # بررسی سرریز افقی در موبایل (۳۹۰px)
node tools/a11y.js                        # ممیزی دسترس‌پذیری خودکار

# باطری کامل QA (پایتون + Playwright + سرور محلی) — همه ۵۴ صفحه:
python3 -m http.server 8801 &             # در یک ترمینال جدا
python3 tools/qa1_pages.py                # خطاهای کنسول/شبکه در هر صفحه
python3 tools/qa2_responsive.py           # اسکرول افقی واقعی در ۸ عرض (۳۶۰ تا ۱۶۸۰)
python3 tools/qa3_valid_links.py          # اعتبار HTML + لینک‌ها و لنگرهای داخلی (نیاز به html5lib)
python3 tools/qa4_interact.py             # جاروی کلیک همه کنترل‌ها و فرم‌ها (خطای JS)
python3 tools/audit_admin.py              # ترازبندی و اندازهٔ آیکون‌ها در ۱۳ صفحهٔ ادمین
python3 tools/deep_audit.py               # ID تکراری، آیکون نامعتبر، دکمهٔ مرده، دسترس‌پذیری ادمین
python3 tools/qa_theme.py                 # هر دو تم: بوت‌استرپ، کلیدهای تعویض، ذخیره، نمودار، کنتراست
python3 tools/qa_light_sweep.py           # اسویپ تم روشن: ۵۴ صفحه × ۲ عرض
```

`qa.py` بدون هیچ وابستگی‌ای اجرا می‌شود و گیت اصلی انتشار است: درصورت ۰ خطا/۰ هشدار، خروجی برای انتشار آماده است.

## امکانات

- **فرمان سریع (Command Palette):** Ctrl/Cmd+K — جستجوی سریع صفحات با پیمایش کیبورد (در ادمین: 14 فرمان + جستجوی زنده در داده‌ها).
- **جستجوی مستندات:** Ctrl+K یا کادر جستجو — فیلتر بر اساس دسته (راهنما/API/SDK/سوالات)، جستجوی اخیر و حالت «پیدا نشد».
- **جستجوی سراسری ادمین:** Ctrl+/ — کاربر/سازمان/اشتراک/فاکتور/تیکت/Request ID/Audit با حالت‌های خالی و بدون‌نتیجه.
- **احراز هویت دمو:** فرم‌های ورود/ثبت‌نام با اعتبارسنجی کامل (ایمیل، موبایل ایران، تکرار رمز) و پیام‌های خطای فارسی.
- **داشبورد:** مودال و دراورها (جزئیات درخواست، ساخت کلید، ارتقای پلن، حذف عضو)، تب‌ها، فیلترهای زنده گزارش درخواست‌ها، صفحه‌بندی، کپی با کلیک (clipboard + fallback)، انتخاب بازه زمانی (۲۴h/۷/۳۰/۹۰) با به‌روزرسانی نمودارها.
- **نمودارها:** Chart.js با برچسب شمسی، اعداد فارسی و tooltip سفارشی + دونات‌های SVG دست‌ساز (بدون کتابخانه) که با تم عوض می‌شوند.
- **تنظیمات:** پنل‌های تنظیمات با deep-link (هش `#`)، تغییر تم، وب‌هوک با ارسال نمونه، حذف فضای کاری با تایپ دقیق «حذف ابرینو».
- **پنل مدیریت:** جدول‌های سازمانی (جستجو/فیلتر/مرتب‌سازی/صفحه‌بندی/انتخاب گروهی)، کشوی جزئیات، مودال تأیید **با تایپ کلمه** در منطقه‌ی خطر، ثبت خودکار همه اقدامات حساس در Audit Logs، خروجی شبیه‌سازی با لودینگ و توست، تغییر محیط Production/Staging/Dev از تاپ‌بار.
- **وضعیت سرویس و تغییرات:** فیلتر دسته‌بندی، انیمیشن نوارهای آپ‌تایم، آکاردئون‌ها.
- **توست‌ها:** سیستم اعلان لحظه‌ای (`aria-live=polite`) برای موفقیت/خطا/هشدار در سراسر محصول.
- **حرکت‌ها:** reveal با IntersectionObserver، هدرهای hover، رعایت کامل `prefers-reduced-motion`.

## معماری RTL

RTL در بلو ورتکس **معماری است، نه افزونه**:

1. **`dir="rtl"` روی ریشه سند** — `<html lang="fa" dir="rtl">` در هر ۵۴ صفحه.
2. **فقط ویژگی‌های منطقی در CSS** — تمام چیدمان با `inset-inline-*`، `margin-inline-*`، `padding-inline-*`، `border-inline-*` و `text-align:start/end` نوشته شده است؛ هیچ `left/right` فیزیکی برای چیدمان جریان وجود ندارد (صفر مورد در ۶ فایل CSS). تنها جایی که جهت فیزیکی لازم است (منوهای آف‌کانواس با `translateX`) با override مشخص `[dir="rtl"]` آینه می‌شود.
3. **جزیره‌های LTR برای محتوای فنی** — URLها، endpointها، JSON، کدها، متدهای HTTP، کلیدهای API، ایمیل، نسخه‌ها و اعداد با `direction:ltr; unicode-bidi:isolate` (کلاس‌های `.ltr`، `.num-ltr`) از بهم‌ریختگی ترتیب فارسی در امان می‌مانند.
4. **اعداد و تاریخ** — اعداد فارسی با گروه‌بندی صحیح (`۱۲۴٬۵۸۰`) از طریق `Intl`/تابع اختصاصی در `main.js`؛ سال بدون جداکننده (`۱۴۰۵` نه `۱٬۰۵`)؛ ارقام لاتین فقط برای شناسه‌های فنی.
5. **ستون‌های عددی** با `font-variant-numeric: tabular-nums` در RTL تراز می‌مانند.

## سیستم تم (تاریک/روشن)

- **مکانیزم:** تم با صفت `data-theme` روی `<html>` انتخاب می‌شود (`data-theme="light"` = روشن؛ پیش‌فرض = تیره). تمام کامپوننت‌ها فقط از توکن‌های CSS می‌خوانند، پس کل محصول (مارکتینگ، مستندات، داشبورد، ادمین) یکجا تغییر می‌کند.
- **بدون فلش:** اسکریپت کوچکی در `<head>` (قبل از CSS) تم را از `?theme=light|dark` یا `localStorage['bv-theme']` می‌خواند و صفت را **پیش از اولین رندر** می‌نشاند.
- **دکمه‌ها:** نوار بالای سایت + منوی موبایل، نوار بالای داشبورد و ادمین، دکمه‌ی ثابت در صفحات احراز هویت و ۴۰۴، و بخش «حالت نمایش» در تنظیمات داشبورد.
- **نمودارها:** `charts.js` رنگ‌ها را از توکن‌ها می‌خواند و با رویداد `bv:theme` همه نمودارها را بدون رفرش دوباره رسم می‌کند.
- **ذخیره:** انتخاب کاربر در `localStorage['bv-theme']` ماندگار است؛ پارامتر `?theme=` اولویت دارد.
- **توکن‌های تم روشن** برای خوانایی روی سفید تیره‌تر شده‌اند (مثلاً `--blue-300` از `#60A5FA` به `#1D4ED8`) و بلوک‌های کد در هر دو تم تیره می‌مانند.

جزئیات کامل (تایپوگرافی، شبکه، حالت‌های کامپوننت، اصول RTL) در `documentation/design-system.md` است.

## معماری مولد (Generator Architecture) — سورس ریپازیتوری

> این بخش فقط برای سورس ریپازیتوری است؛ بسته‌های بازار `tools/` را ندارند.

**قاعده‌ی طلایی:** فایل‌های HTML **خروجی** هستند. هرگز مستقیم ویرایش نکنید؛ تغییرات را در مولد مربوطه اعمال و با `python3 tools/build.py` بازتولید کنید.

```
tools/
├── build.py          # ارکستراتور: b() خروجی ۵۴ صفحه را می‌سازد؛ seo_extras() هر بیلد
│                     #   robots.txt + sitemap.xml + 404.html را نوسازی می‌کند و
│                     #   canonical/og:url هر صفحه را مطلق و خودصفحه (self-canonical) می‌کند
├── chrome.py         # تنها قالب <head> سراسری + ناوبری/فوتر/سایدبارها/پالت + اسکریپت‌ها
├── marketing_home.py       # مولد index.html
├── marketing_pages.py      # مولد ۷ صفحه pages/
├── blog_contact.py         # بلاگ + تماس
├── auth.py                 # ۳ صفحه احراز (شِل مشترک auth_shell)
├── docs_pages.py           # شِل و کمکی‌های مستندات (doc_page)
├── docs_content.py / docs_content2.py   # محتوای ۱۵ صفحه مستندات
├── dash.py / dash2.py / dash3.py        # ۱۱ صفحه داشبورد (شِل مشترک dash_page)
├── misc.py                 # changelog + status
├── admin.py                # ۱۳ صفحه ادمین (build_all)
└── qa*.py / *.js           # ابزارهای کنترل کیفیت
```

**نحوه‌ی افزودن صفحه جدید (مثال):** یک تابع `build_xxx(prefix)` در ماژول مناسب بسازید که از `chrome.head()`، `chrome.navbar()`، `chrome.footer()` و `chrome.scripts()` استفاده کند، سپس یک خط `emit('path/new.html', build_xxx('../'))` به `b()` در `build.py` اضافه کنید و بیلد بگیرید. canonical و og:url خودکار درست ساخته می‌شوند.

**پیشوند مسیرها:** مولدها عمق صفحه را می‌دانند: `''` برای ریشه، `'../'` برای دایرکتوری‌های یک‌سطحی، `'../../'` برای `docs/api/`.

**خروجی‌های خودکار هر بیلد:** `robots.txt` (با Disallow برای `admin/ dashboard/ auth/`)، `sitemap.xml` (فقط صفحات عمومی، بدون تکرار، `lastmod` = تاریخ بیلد) و `404.html` (noindex، بدون canonical).

## نحوه سفارشی‌سازی

### برای همه (بسته‌های بازار و سورس ریپازیتوری)

| تغییر | کجا |
|---|---|
| رنگ‌ها و توکن‌ها | متغیرهای CSS در ابتدای `assets/css/base.css` (`:root` و `:root[data-theme="light"]`) |
| فونت | فایل‌های `assets/fonts/` (OFL) + بلوک‌های `@font-face` در `base.css` |
| داده‌های نمایشی پنل مدیریت | `assets/js/admin-data.js` — منبع واحد `window.ADMIN`؛ همه صفحه‌های ادمین هماهنگ به‌روز می‌شوند |
| تصویر اشتراک‌گذاری | `assets/og/og-cover.jpg` (1200×630) |
| آیکون | `assets/icons/favicon.svg` |
| متون صفحات (بسته‌های بازار) | مستقیم در فایل HTML مربوطه — بسته‌ها مولد همراه ندارند، ویرایش مستقیم HTML مجاز و ساده است |

### فقط سورس ریپازیتوری (از طریق مولد، سپس بیلد — در بسته‌های بازار موجود نیست)

1. **تغییر برند:** نام محصول، توضیحات متا، ناوبری و فوتر در `tools/chrome.py` (توابع `head`، `navbar`، `footer`) و دامنه در `SITE` داخل `tools/build.py`.
2. **تغییر محتوای صفحه‌ها:** در ماژول مولد صفحه مربوطه (لیست در بخش معماری مولد) — داده‌ها به‌صورت لیست‌های خوانا در ابتدای توابع تعریف شده‌اند.
3. **صفحه جدید / حذف صفحه:** از `b()` در `build.py` (قسمت قبل).
4. **تغییر canonical/SITE:** فقط `SITE` در `build.py` — canonical/og:url/سیت‌مپ همه خودکار به‌روز می‌شوند.

پس از هر تغییر: `python3 tools/build.py && python3 tools/qa.py` (باید ۰ خطا).

## پنل مدیریت (Admin Console)

بلو ورتکس چهار لایه دارد: سایت بازاریابی، مستندات، کنسول توسعه‌دهنده (برای مشتریانی که از API استفاده می‌کنند) و **پنل مدیریت** (لایه‌ی ۴) برای مالک، اپراتور و تیم پشتیبانی پلتفرم.

### تفاوت Developer Console با Admin Console

| | کنسول توسعه‌دهنده (`dashboard/`) | پنل مدیریت (`admin/`) |
|---|---|---|
| کاربر | مشتری/توسعه‌دهنده | مالک، اپراتور، تیم پشتیبانی |
| تمرکز | کلیدها، مصرف، صورتحساب خودش | سلامت پلتفرم، مشتریان، درآمد کل |
| حالت ذهنی | «از API استفاده می‌کنم» | «پلتفرم را کنترل می‌کنم» |
| نشانهٔ بصری | برند DEVELOPER CONSOLE | برند ADMIN CONSOLE + نوار اکسنت بالایی + نشانگر محیط |
| آدرس | `dashboard/*.html` | `admin/*.html` |

### ساختار صفحات

- **نمای کلی** — ۸ KPI، نمودار MRR و رشد کاربر، سلامت ۸ سرویس، هشدارهای اولویت‌دار، تایم‌لاین
- **کاربران / سازمان‌ها / اشتراک‌ها** — جدول‌های سازمانی با جستجو، فیلتر، مرتب‌سازی، صفحه‌بندی، انتخاب گروهی (bulk) و کشوی جزئیات
- **درآمد** — MRR/ARR/LTV/ARPU/چرخش، فاکتورها، پرداخت‌ها (با دلیل شکست) و بازهٔ ماهانه/هفتگی/روزانه
- **مصرف API** — ترافیک، رتبه‌بندی سازمان‌ها، مرکز خطاها، عملکرد Endpoint (P50/P95/P99)
- **فعالیت سیستم** — تایم‌لاین استقرار/پیکربندی/امنیت + Incidentها با شدت و تیم مسئول
- **پشتیبانی** — تیکت‌ها با اولویت (آیکون + برچسب + رنگ)، گفتگو، یادداشت داخلی، حل تیکت
- **اعلان‌ها / محتوا / Feature Flags** — مرکز اعلان با فیلتر نوع؛ بلاگ/مستندات/Changelog/اعلان؛ توزیع تدریجی با تأیید
- **امنیت** — رویدادهای امنیتی + Audit Logs با نمای قبل/بعد
- **تنظیمات سیستم** — پیکربندی، ماتریس مجوز نقش‌ها، پروفایل و نشست‌ها، **منطقهٔ خطر با تأیید تایپی**

### تعاملات کلیدی

`Ctrl+K` پالت فرمان · `Ctrl+/` جستجوی سراسری · Esc برای بستن هر لایه · تغییر محیط از تاپ‌بار (نشانگر رنگ‌دار) · هر اقدام حساس: مودال تأیید (با تایپ کلمه در منطقه‌ی خطر) + ثبت خودکار در Audit Logs · خروجی CSV/JSON شبیه‌سازی با لودینگ و توست.

### نحوهٔ اتصال Backend

این قالب استاتیک است و بک‌اند ندارد؛ برای اتصال واقعی، کافی است داده‌های `admin-data.js` با فراخوانی REST/GraphQL جایگزین شوند (قرارداد فیلدها در همان فایل مستند است). UI هیچ وابستگی به منبع داده ندارد: ۱) بارگذاری داده → ۲) گرفتن مدل → ۳) `renderTable(entity)` برای رندر مجدد.

### وضعیت کیفیت

- `ADMIN_QA_REPORT.md` — گزارش کامل QA لایه‌ی ادمین (۳۴ مورد با ریشه، رفع و تأیید + باطری نهایی ۵۴ صفحه)
- `ADMIN_TRACEABILITY.md` — ماتریس ردیابی ۴۵ نیازمندی → صفحه → پیاده‌سازی → تست
- صفر خطای کنسول در ۱۳ صفحه؛ ترازبندی آیکون‌ها و چیدمان موبایل (۳۹۰–۱۴۴۰) ممیزی‌شده؛ نمودارهای توزیع با همان کامپوننت داشبورد؛ لایه‌های ۱–۳ بدون تغییر و سالم.
- **QA نهایی محصول (همه ۵۴ صفحه):** صفر خطای کنسول/شبکه (qa1)؛ صفر اسکرول افقی در ۳۶۰/۳۹۰/۴۱۴/۷۶۸/۱۰۲۴/۱۲۸۰/۱۴۴۰/۱۶۸۰ (qa2)؛ HTML معتبر و صفر لینک/لنگر مرده (qa3)؛ صفر خطای JS پس از کلیک روی همهٔ کنترل‌ها و ارسال فرم‌ها (qa4)؛ همهٔ دیپ‌لینک‌ها در مرورگر فعال‌اند.
